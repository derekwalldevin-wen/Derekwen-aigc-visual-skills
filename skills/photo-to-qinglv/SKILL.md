# 照片入青绿

需要可读取图片且支持实际参考图编辑的图像工具；无此能力时只交明确标注的提示词，不声称完成转绘。

## 输出与入口

默认交付一张3:4竖版图片，上方摄影、下方青绿转绘，标题融入两区之间的绢白负空间。使用同一照片作为场景锚点，不重新设计地点或把现代人物古装化。用户只要提示词时交提示词；只要整理Skill时不生成新图。

已有用户指定照片则直接读取；没有照片时请用户上传，或在用户明确选择生成示例后先生成写实输入图，再以实际参考图编辑。不能只靠文字分别生成两个相似场景来冒充同图转绘。AI生成的写实输入标为“AI写实示例”，真实上传照片才可标为“原照片”。

## 输入与变量

- 【源图】：可读取的授权照片／明确标注的AI写实示例；优先用户上传原图。
- 【主体／场景】：从源图识别人数、服装、物件、建筑、道路和水岸关系，不凭空替换。
- 【配色】：石青、石绿、赭石、少量原图对应的朱砂暖色。
- 【构图】：默认3:4，上方约45%摄影、下方约55%青绿转绘，中间绢白留字。
- 【输出模式】：默认有字上下双生；纯视觉模式为未独立实测的可选扩展。
- 【文字模式】【中文标题】【英文标题】【上图标签】：母模板的四个必填变量。AI写实输入必须标注“AI写实示例”。

## 执行

1. 查看输入图，记录人物数量、服装、姿态、车辆或主要物件结构、建筑轮廓、道路水岸关系、光向和可用留白。照片空间关系优先于青绿装饰。
2. 读取[最终母模板](references/mother-template-v1.txt)，填写四个变量：文字模式、中文标题、英文标题、上图标签。有字模式标题采用瘦金体笔意；英文短而准确。纯视觉模式四个变量仍填完，但不产生任何文字。
3. 实际将输入图传给参考图编辑工具，不仅描述“参考照片”。复测基线时只替换四个变量，不私加场景定制句。用户要其他比例或布局可改，但记录新版本，不称已由本组三例验证。
4. 调用图像工具生成，画面与文字一并生成；此工作流不靠程序后期叠字。默认约45%摄影、55%转绘，以连续暖绢白协调，不套相邻几何双生Skill的硬框、强制硬分割或跨框规则。
5. 查看实际结果，并对照原输入。需要修正时指出具体错误，重试只修失败项，保留通过结果。没有图像工具或无法读取结果时如实说明，不把提示词、路径或调用计划当成图片。

## 青绿与文字设计

以细劲墨线、石青石绿罩染、赭石底色和绢本肌理转换画风，现代建筑、车、服装仍然是原物。朱砂呼应原照片已有暖色，不凭空新增红色道具。不要增加山峰遮盖城市，不用泛化古风替换真实生活。

标题瘦硬挺拔、转折锐利、长撇捺舒展，中文约英文4倍，深墨青字与主体线势呼应。保持字义正确、手机可读和连续负空间，不把普通宋体或粗行草称为瘦金体。这里是AI生成的“瘦金体笔意”字形，不是提供字体文件或书法真迹。

## 验收与失败纠偏

- 画幅正确，摄影与转绘上下可对照；主物件完整，不镜像或拉伸。
- 核对人物、服装、人数、车窗车轮、船体、建筑和道路水岸。新增删改关键结构、换脸换衣或构图明显错位：固定源图结构后局部重新编辑。
- 检查中文、英文和标签逐字正确；乱码、漏字、非预期印章或文字压住主体：缩短文本并调整绢白留白。
- 青绿只有蓝绿滤镜、没有笔墨和绢质：增强细劲墨线、层染与赭石底色；不要把现代场景改成古代。
- 上下不对应：同一输入源图再次编辑，锁定机位、物件数量和左右次序。
- 摄影区被重绘：提高摄影区的真实质感保留约束；需要像素无损时另行使用原片后期拼版，不夸大当前编辑工具能力。
